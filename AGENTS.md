# AI Tools Launchpad

A single Cloudflare Worker (TypeScript) that server-renders the "AI Tools Market Radar"
site. There is no database, no bundler config, and no external runtime services — the
Worker imports static data from `src/toolify-data.ts` and renders HTML/JSON directly.

## Cursor Cloud specific instructions

### Services

There is one service: the Cloudflare Worker, run locally via `wrangler dev` (Miniflare/workerd).

- Run (dev): `npm run dev` (equivalent to `wrangler dev src/index.ts`). It serves on
  `http://127.0.0.1:8787` by default. To bind all interfaces use
  `npx wrangler dev --ip 0.0.0.0 --port 8787`.
- Lint / typecheck: `npm run check` (`tsc --noEmit`). This is the only "lint" gate; there
  is no ESLint config and there are no automated tests in this repo.
- Build/deploy (do not run in the cloud VM): `npm run deploy` requires
  `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` and pushes to production. Skip it.

### Non-obvious notes

- `wrangler dev` runs fully local (no Cloudflare login) for this Worker, since it has no
  bindings. It does not require any secrets to run or to serve every route.
- `tsconfig.json` uses `allowImportingTsExtensions`, so intra-repo imports use explicit
  `.ts` extensions (e.g. `import { toolifyData } from "./toolify-data.ts"`). This is
  expected and required — do not "fix" these to extensionless imports.
- Useful routes to sanity-check the running Worker: `/` and `/zh` (HTML home, EN/ZH),
  `/health` (JSON), `/api/toolify` (JSON data), `/sitemap.xml`, `/robots.txt`, and dynamic
  detail pages like `/radar/<section-key>/<slug>` (e.g. `/radar/high-traffic-categories/ai-chatbot`).
- `src/toolify-data.ts` is auto-generated by `scripts/update-toolify-data.mjs` (run hourly
  by a GitHub Action). It fetches Toolify rankings via `r.jina.ai` and falls back to curated
  data when the network is blocked; you normally do not need to run it during development.
